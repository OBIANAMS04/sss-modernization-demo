Sign-in asks for a second step

  • An authenticator app adds a 6-digit code.
  • A password alone never gives a session.
  • Five tries, each code once, every step logged.
Scene 13, two-step verification (STORY-003). On Sign-in security a person scans a QR code with Google Authenticator, Authy or Microsoft Authenticator, or types the key, and confirms with a 6-digit code. From then on, a correct password earns only a five-minute pending token that every page and the session refresh refuse; the code completes the sign-in. Five tries per sign-in, each code accepted once, and every step is in the audit log without the key or the code. Our own review found that a pending sign-in could be used twice to get a second session; it was fixed before shipping, and a test that reproduces it guards it.
