What the demo does today

sss-demo-frontend.onrender.com · synthetic data only; demonstrated on a demo deployment, not operating in production. The first visit after idle takes about 50 seconds while the free server wakes.

  • Secure sign-upPasswords and SSNs stored as bcrypt hashes; 1-hour sessions; masked SSN entry
  • Profile and compliancePhone, address, income and hardship; checks 18+, phone and address
  • Exemption eligibilitySenior (65+), income (under $20,000), hardship (caseworker review), each with a reason
  • Case managementSubmitted → In Review → Approved or Denied, appeals, timeline and internal notes
  • Compliance validationEvery decision checked against 8 controls; a failure is reviewed by a second case manager; dashboard with a 99% target and a full audit log
  • Data freshnessEvery change timed until the next request can read it; per data type against 30 s for 95% of updates, with an alert and the slowest updates
  • NotificationsApplicants are notified of every status change, with the reason
  • Security audit logEvery sign-in, refusal, read, export, change, role grant, deployment and configuration change, with who, when and from where; the database refuses edits and deletions; kept 7 years; no SSNs, passwords or secrets
  • AccessibilityEvery page passes WCAG 2.1 AA checks for each role: keyboard and skip link, screen-reader names and errors, contrast, 320 px reflow; a warning before a session ends; confirmation before applying or appealing
  • Citizen dashboardEach application with its status and next step, eligibility with reasons, recent activity and notifications; only your own
  • Roles and Staff AccessCitizen, case manager, leadership and administrator. Administrators give or remove case manager, leadership and administrator access; case managers only case-manager access. Always with a reason; never your own, never the last case manager or administrator; every change logged. ADMIN_EMAILS sets up the first administrator from existing case managers; on Oct 14 the owner's case-manager account became the demo's administrator
  • Two-step sign-inQR code and key for an authenticator app; after the password a 5-minute pending token that every route refuses, then a 6-digit code (one 30-second step either side, never the same code twice, 5 tries); turning it off needs a code; the key is shown once; every step audited without the key or code. A double-redeem gap found in our own review was fixed before shipping
  • Case manager dashboardMy open cases, waiting on me (to start, to decide, compliance reviews of others' decisions), unassigned queue, overdue (over 5 days without an update), recent decisions, and a search that opens the filtered case list
  • Admin dashboardAll cases by status and type, team performance (open, decided, median days to decide, compliance pass rate), system health (database and migrations, deployed commit, freshness against 30 s, compliance against 99%, refusals in 24 hours, staff by role)
  • Leadership dashboardTotal applications, approval rate, average processing time, open cases, appeal rate, 12-week trends, bottlenecks by stage and team performance; aggregates only, no applicant data
  • Policy assistantAsk about exemptions, documents, appeals or privacy; answers come only from 8 synthetic policy documents, with numbered citations that open the quoted text, and each is checked against the policy before anyone sees it. The assistant never decides eligibility: questions about your own case, answers that fail the check and answers people report go to a case manager, who approves, corrects or declines; you are notified. Claude answers on the live demo since Oct 20
  • Override rateHow often staff went against what the system said (assistant answers, compliance exceptions, eligibility), with a 12-week trend against a target below 20%, on the admin and leadership dashboards
  • Drift detectionNine quality signals from real AI answers compared week on week, evaluation runs against a baseline, change markers, and alerts to administrators
  • FairnessNames, places, phrasing and stated identity must not change outcomes or answers; outcomes compared by age band and region with the four-fifths rule; no race, sex or similar data collected
  • ObservabilityTrace ids on every response and log line, per-route latency and errors, AI tokens and cost, objectives checked every minute with alerts and a runbook; export to Datadog or any OpenTelemetry backend is one setting
  • Load and performanceLoad tested to 128 connections locally and 25 live; throughput about doubled and no request fails after the fixes (before, a full connection pool closed every route). Production sizing for 10,000 users, every number labelled measured, derived or assumed
  • Database outageThe API keeps running without its database, answers "try again" with Retry-After, and recovers by itself without a restart; the multi-region production design is written (not deployed)
  • Uptime checkEvery 30 minutes from outside Render; a failure opens a GitHub issue and recovery closes it
  • Security hardeningSign-out ends the session on the server; sign-in and registration throttled; security headers on the API and a content policy on the site; ten one-time recovery codes for two-step sign-in; an attack suite of 52 checks
  • Accessibility conformance reportVPAT 2.5 for WCAG 2.1 A and AA and Section 508, honest about the screen-reader test still owed
  • Operations documentsIncident playbook, operator runbook, administrator guide and user guide
  • Data statusThe citizen dashboard says how current the page is: when your records last changed and how quickly changes become visible (green, yellow or red, in words too)
  • Access policiesOpen Policy Agent decides every API request before any route: role, resource type, action and owner or assignee. Administrators change rules without a deploy (reason required, write-once versions, audited, applies at once). The policy can refuse what the code allows, never allow what it refuses; sign-in, health and the policy pages are locked so administrators cannot be locked out. The earlier "API governance" service never called OPA and was removed

Platform

Claude commits and pushes each change, and Render deploys automatically. Claude then verifies the demo deployment itself: the commits served on every page path, the database and migrations, every protected route refusing requests without a token or from a citizen, and screenshots. Database changes apply on startup through tracked migrations (001–027). Open Policy Agent decides every API request before any route runs; the access table lists 68 routes. Every request is traced with OpenTelemetry and measured per route. The policy assistant uses Claude when ANTHROPIC_API_KEY is set, and is scored by scripts/ai/eval.mjs. The policy is checked end to end by scripts/e2e/policy.mjs and built by scripts/opa/build.mjs. Load is measured by the harness in scripts/load/, a database outage by scripts/e2e/failover.mjs, attacks by scripts/e2e/security.mjs, and an uptime check outside Render runs every 30 minutes.
